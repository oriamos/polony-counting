# Legacy code audit (`src/polony`, `src/models`)

Scope: each suspected problem of the legacy neural-network pipeline was checked by reading the code and, where possible, by **running it**. Torch is not installed here (and was not installed), so the executed checks
use a small mock harness that stubs `torch`, `torchvision`, `wandb`, etc., loads the **real** `src/polony/models/predict_model.py` and the real `get_concentration_factor` source, and calls the real functions
(script kept outside the repository). Findings that need real torch behaviour are marked "read only".

**Legacy code is left untouched** (`git diff main -- src/polony src/models` is empty) **and the checkpoints are preserved**: `src/polony/checkpoints/{classifier_57_0.8896.pth, unet_49_1.7496.pth, test.pth}`.
The new app (`src/polony_app`) does not import torch or any legacy module and does not use the checkpoints.

Line numbers refer to `src/polony/models/predict_model.py` unless stated otherwise.

## Additional observations (not in the original list)

* **`read_tiff` scaling** (`src/polony/data/utils.py:92`): divides by 255 regardless of dtype, so a 16-bit image yields values up to 257; the normalisation constants (`MEAN`, `STD`, `:38`) are presumably matched to that. Read only; not verified against training. The new app keeps the original dtype and never rescales for detection.
* **Mutable/expensive defaults** (`:83,85`): `UNet(res=False)` and `Classifier()` are instantiated at import time as default arguments and are shared between calls.
* **CSV format drift**: the legacy writer's header (`:285-295`) has a leading `TYPE` column and no `QC` column; the researcher's current CSVs have no `TYPE` but have `QC`. `efficacy` code reads `slide ID` and `FAGE ABUNDENCE [fage mL-1]`, ignores `QC` and averages rows per slide (`polony_to_phage.py:68-72`).
* **Blank vs zero lost**: a slide with no valid squares yields average 0 (`:260-262`), i.e. an abundance of 0 instead of "not counted".
* **Efficacy docs**: `alpha` is documented as a "confidence level" but is used as a significance level (`quantile([alpha/2, 1-alpha/2])`), so 0.05 gives a 95 % interval; the slope tables are hard-coded constants (`polony_to_phage.py:28-34`) whose origin is not documented here; the bootstrap is a Python loop of `n = 10000` iterations.
* **Tests**: the legacy tests mock almost everything (and `test_predict_*` expect list-shaped results), so they do not exercise the failing paths above. They could not be run here (no torch).
* **No end-to-end legacy run**: none (image -> CSV) is possible without fixing items 1-5; no fixes were applied because the legacy code must stay untouched.

## How to reproduce

The mock harness (about 80 lines) is not part of the repository; the logic is: stub the heavy modules in `sys.modules`, load `predict_model.py` with `importlib.util.spec_from_file_location("polony.models.predict_model", ...)`, call `predict(<file>)`,
`predict(<dir>)` with `predict_one_image` patched, `main(args)`, and `save_predictions_to_csv` with the output of the real `predict_one_image` (fed a fake network). The results quoted above are its output.
